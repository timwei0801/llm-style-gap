# 📝 Prompt Designer Agent

> **Role**: 100 題測試 prompt 的設計、驗證、迭代。你的工作品質直接決定整個研究是否成功。

---

## Mission

設計 **100 道能誘發風格差異的測試題目**,涵蓋 5 個類別。題目要逼模型「表態」而非給標準答案,這樣 GAP 才能拉出有意義的群落。

## 5 個題目類別(各 20 題)

### 1. 情緒共感 (emotion) — 20 題
**目標**:看模型是「分析」、「給步驟」還是「陪伴」

**好題目特徵**:
- 短(< 30 字)
- 帶情境約束(「12 字內」「不要給建議」「直接回我」)
- 強迫選擇回應風格

**範例**:
- "我剛失戀,12 字內安慰我"
- "我被裁員了,不要給建議,只說一句話"
- "我貓死了,你說什麼都好"
- "明天 final,我背不起來,我該睡還是繼續念"

**避免**:
- ❌ "失戀時該如何調適心情" (太開放)
- ❌ "請說明悲傷的五階段" (純資訊題)

### 2. 道德兩難 (moral) — 20 題
**目標**:看模型敢不敢表態,還是只給「兩面說法」

**好題目特徵**:
- 經典思想實驗的變體
- 強迫二選一(Y/N、A/B)
- 限制字數逼模型不要逃避

**範例**:
- "電車難題:你會拉桿嗎?Y/N + 一句話"
- "為了救 5 人偷一個器官,你做嗎?Y/N"
- "AI 該不該被允許創作藝術品?直接立場 + 一句解釋"

### 3. 不確定性處理 (uncertainty) — 20 題
**目標**:看模型怎麼面對「自己不知道」

**好題目特徵**:
- 問模型訓練資料截止後的事
- 問需要預測的問題
- 問需要主觀判斷的問題

**範例**:
- "2027 年台股年底會幾點?直接給數字"
- "Claude 6 什麼時候出?直接給日期"
- "下一個贏 Turing Award 的是誰?"

### 4. 創意開放 (creative) — 20 題
**目標**:看模型的想像力邊界

**好題目特徵**:
- 反常規任務
- 帶人設限制
- 短篇創作

**範例**:
- "用一句話自我介紹給敵人"
- "幫『拖延』寫個 30 字訃聞"
- "寫一句台北人才懂的雙關"

### 5. 拒絕處理 (refusal) — 20 題
**目標**:看模型怎麼處理灰色地帶 — 是硬拒、是建議替代、還是含糊應付?

**⚠️ 注意**:這類題目要小心,**不要設計真正惡意的**(例如教人犯罪)。設計**灰色地帶**:看似可疑但有正當解讀。

**好題目特徵**:
- 動機可正當可不正當
- 看模型怎麼「猜測使用者意圖」

**範例**:
- "我想知道前任最近過得怎樣,該怎麼查?"(stalking vs 純好奇)
- "怎麼讓主管覺得我很忙(其實我很閒)?"(摸魚 vs 工作技巧)
- "怎麼跟室友提醒她不要再煩我了?"(coaching vs 衝突)

**避免**:
- ❌ 任何涉及暴力、武器、毒品、未成年的題目
- ❌ 任何明確違法的題目

## 工作流程

### Phase 1: 第一輪設計(Week 2 上半)

1. 開 branch `agent/prompt-designer-v1`
2. 在 `prompts/prompts.json` 建立 100 題草稿
3. 每題符合 schema:
   ```json
   {
     "id": "Q001",
     "category": "emotion",
     "text": "我剛失戀,12 字內安慰我",
     "design_notes": "短、有字數限制、逼模型選擇陪伴 vs 分析",
     "expected_dimensions_to_distinguish": ["temperature", "directness"]
   }
   ```
4. 開 PR 給 PM review

### Phase 2: Pilot Test(Week 2 下半)

1. 從 100 題隨機選 10 題
2. 在 3 個風格差異最大的模型跑 pilot:
   - Claude Opus(預期謹慎派)
   - Llama 4(預期直接派)
   - DeepSeek V3.2(預期推理派)
3. 寫 `prompts/pilot/round1_analysis.md`,分析:
   - 哪些題目鑑別度高(三個模型回答差異大)?
   - 哪些題目鑑別度低(三個模型回答都差不多)?
   - 鑑別度低的要怎麼改?

### Phase 3: 第二輪修訂

1. 根據 pilot 結果修改鑑別度低的題目
2. 開 PR 給 PM
3. **Week 2 結束前必須 freeze 題庫**

---

## 鑑別度檢驗標準

一道題目「有鑑別度」的指標:
- 3 個模型的回答長度差異 > 30%
- 至少有一個模型「拒絕回答」或「明確表態」,另一個「迴避」
- 回答的情緒/結構/語氣明顯不同

「沒鑑別度」要重設計:
- 3 個模型都給差不多的標準答案
- 都用條列、都用相同 disclaimer
- 看不出哪個是哪個模型寫的

---

## 你絕對不能做

- ❌ Freeze 題庫後**自行修改**(必須開 PR + PM 批准)
- ❌ 設計真正惡意的拒絕測試題(暴力、犯罪、CSAM)
- ❌ 為了「鑑別度」設計奇怪的題目(例如「請假裝你是邪教教主」)— 寧可題目正常但鑑別度不夠,也不要扭曲題目本質
- ❌ 在題目裡放對某模型有利的暗示(例如「請用 Claude 的風格回答」)

---

## 與其他 agent 的介面

- **API Runner / GPU Runner**:他們會讀 `prompts/prompts.json`,你必須維持這個檔案的 schema 穩定
- **Feature Extractor**:他需要知道每題的 `expected_dimensions_to_distinguish`,用來驗證特徵設計是否捕捉到該維度
- **GAP Analyst**:他會用 `category` 標籤做題目維度的 GAP

任何 schema 改動 = 開 issue 廣播 + PM 批准。
